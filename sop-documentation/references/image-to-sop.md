# 从界面截图编写 SOP

## 适用场景

用户提供多张后台或编辑器截图，希望把操作过程整理成培训或测试文档。先确认图片顺序：用户可能按倒序发送，不能按附件接收顺序直接编号。

## 编写规则

- 先建立“目标 → 页面入口 → 点击对象 → 页面反馈 → 下一步”的链路，再写成编号步骤。
- 只描述截图中能确认的控件。看不清的文字标为“待确认”，不要凭经验补按钮名。
- 图注描述当前图片展示的关键对象，不重复整段操作说明。
- 若用户指定某张图需要图注（例如最后一张图要有三个图注），按指定数量拆分为局部说明，并保持顺序清晰。
- 对图层、房间、区域、工位数量等容易点错的对象，使用位置和层级描述，例如“左侧图层列表”“上方房间/区域入口”“最右侧被点击项”。
- 删除、合并或保存前写确认步骤；界面有撤销、预览或暂存时，说明如何回退。

## 工位编辑会话中的已知流程

该会话要求把五张图片按倒序理解：倒数第一张图片需要三个图注；左侧图层加框；在上方选择“房间”区域；点击最右侧目标；然后选择工位数量。整理时应把这些要求拆成连续步骤，并让每个图注对应一个可见界面状态。若后续补充了真实按钮名或截图顺序，以新证据为准。

## 交付检查

- 图片编号连续且与图片实际顺序一致。
- 每个关键点击都能在图片或文字中定位。
- 操作员不需要根据推测理解下一步。
