# 语义地图建图 SOP 参考

这份参考整理自“编写语义地图制作 SOP”会话，供需要复用同类流程时按需读取。页面按钮名称和部署目录以当前项目实际界面为准。

## 流程范围

在线建图 → 人工质检 → 房间标注及拓扑调整 → 地图部署。ROS bag 采集本身引用项目提供的采集文档，不在本 SOP 重复展开。

## 在线建图

1. 打开数据生产导航页：`http://10.136.107.10:8899/?view=nav`。
2. 进入“地图生产 → 语义建图”，选择数据集 `XR`。
3. 上传 ROS bag 对应的 `.mcap` 或 `.zip`，保持“上传完成后自动提交建图”，点击“上传并建图”。不要重复提交同一个包。
4. 页面默认高级参数用于测试；只有任务明确要求时才修改。完成后进入“地图库 → 地图”，按 `XR` 找到已完成版本，核对数据包名称、版本号、耗时和来源，打开预览确认语义物体、房间区域和拓扑骨架正常。

## 人工质检

1. 进入语义地图的“交互导航 → 物体与拓扑”。确认物体、物体框、拓扑点、拓扑边和 object-road 绑定已显示。
2. 按房间逐个检查物体：重复识别、错误类别、框或 mask 不对应、位置漂移，以及物体落在墙外或房间外。
3. 同一真实物体被识别为多个 instance 时，逐个“加入合并候选”，选择主实例，必要时取消错误观测，再“合并并立即预览”。类别相同但位置和证据表明是两个独立物体时不得合并。
4. 类别错误使用“修改 label”；实际不存在或全部观测错误使用“删除 instance”。检查暂存列表，错误操作先撤销。
5. 确认暂存操作后点击“保存修改并刷新地图”，再到“地图库 → 地图”下载对应的最新完整地图输出。保留 `map.db`、`map_ingest_summary.json`、`scene_room_*.dsgz` 以及 `2d_map`、`3d_map` 等资产。

## 房间标注与拓扑调整

1. 打开 Viewer：`http://10.136.107.10:8000/static/index.html`，进入“编辑”。
2. 点击“导入地图”，选择人工质检下载并解压后的完整输出文件夹（应包含 `2d_map` / `3d_map`），再点击“导入DB”选择输出的 `.db` 文件。
3. 进入“语义编辑”：用“拓扑点”加点，用“移动点”调整位置，用“拓扑边”连接两个节点，用“删边”移除错误连接，用“删点”删除拓扑点。删点会连带删除连边，执行前必须确认。
4. 检查物体与拓扑点的连边。物体附近缺点时先补可达拓扑点，再接入主拓扑网；删除穿墙、跨封闭区域或明显错误的边。
5. 在“区域”工具中选择“多边形”，沿房间边界闭合区域；边界不得穿墙或与其他房间大面积重叠。闭合后填写房间“名称”和必要的“描述”，点击“保存”。名称应清晰、唯一并与现场一致。
6. 点击“校验”，修正房间重叠、孤立点或异常连边；校验通过后点击“导出DB”，重新导入检查房间、拓扑和物体连接。

## 地图部署交付

操作员只需把完整地图目录放到项目指定的地图根目录，并按项目约定设置环境变量；不要只部署单个 DB，也不要引入 `.active_db` 等未被 Agentic VLN 读取的切换文件。

地图目录通常为：

```text
/opt/xr/turing/map_data/<map_name>/
```

保留 Viewer 导出的完整资产，包括 `map.db`、`2d_map/`、`3d_map/`、`nav_point/`、`keyframe/`、`description.yaml`，以及语义侧的 `map_ingest_summary.json` 和 `scene_room_*.dsgz`。如流程产物名为 `merged.db`，按项目约定备份旧 DB 后，将新文件放回原位置并保持运行时要求的原文件名 `map.db`。

环境变量示例：

```bash
export DEFAULT_MAP_NAME=<map_name>
export NAVCTL_LOCALIZATION_MAP=<map_name>
export MEMORY_MAP_DB=/opt/xr/turing/map_data/<map_name>/map.db
export MAPDB_MODEL_DIR=<Agentic-VLN路径>/services/memory_module/models
```

不要把机器人定位原生地图目录、语义地图目录和服务模型目录混为一处；实际路径以部署项目的配置为准。
