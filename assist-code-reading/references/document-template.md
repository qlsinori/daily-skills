# Code-reading document template

Use this as a starting point, then remove sections that do not apply.

```markdown
# <项目>：训练与推理链路（代码导读）

> 目标：读者能够从入口文件一路跟到模型输出，并知道哪些步骤已验证。

## 1. 项目边界与目录

- 当前代码负责什么
- 不负责什么
- 关键目录和入口

## 2. 先建立输入输出概念

| 名称 | 代码位置 | 形状/单位 | 白话解释 |
|---|---|---|---|

## 3. 一张调用链图

```text
入口 -> 预处理 -> 编码器 -> 模型/扩散 -> 选择动作 -> 环境或 HTTP 输出
```

## 4. 推理调用链

### 4.1 入口
### 4.2 预处理与历史状态
### 4.3 模型前向/扩散采样
### 4.4 动作或轨迹后处理
### 4.5 API/评测调用示例

每个小节都把“代码链接/片段”和“这段代码在做什么”放在一起。

## 5. 训练调用链

### 5.1 数据如何进入 batch
### 5.2 条件、噪声和 loss
### 5.3 optimizer/checkpoint
### 5.4 可运行命令和结果

如果没有训练代码，明确写“仓库未提供”，再说明可见的 checkpoint 或下游训练入口。

## 6. 术语翻译表

把代码中的词翻译成这个项目里的具体对象。

## 7. 典型形状、单位和边界

记录图像通道顺序、深度单位、坐标系、时间窗口、动作语义和停止条件。

## 8. 常见问题与限制

区分代码事实、局部补丁、外部资产要求和未验证的部分。
```
