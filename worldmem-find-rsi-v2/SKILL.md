# 根据证据找物

本流程补充原生找物的任务准备，不替换导航、相机或找物模块。仅使用本题提供的历史、输入地图、工具返回的当前观察。地图是旧记录，不能当作当前答案。

## 开始前

1. 确定要找的完整对象。颜色、外观、关系不能丢掉；`target` 保留完整描述，`detect_as` 只放英文物体类别。不要把颜色只写在备注里。
2. 题目用“历史里的物体”“某轮找到的物体”指代目标时，先用 `mem_recall_episodes` 查询对应记录，再确定对象。查询无结果不等于物体不存在；换用题目中的历史编号或关键词，不能猜一个对象代替。
3. 用允许的地图和历史决定先看哪里。不同房间里的同名物体分别检查；从工具拿到的实体编号才可以用于引用。不要根据旧地图中的颜色或位置直接宣布找到。
4. 用户限定了搜索范围，`areas` 必须包含完整范围，并使用 `only_areas=true`。题目没有限定房间时，不要把“通常会放的几个房间”当成全部范围；find 步骤的 `phrase` 明确写为“全屋找”加完整对象描述，允许继续检查其他房间（原生模块从该字段识别全屋范围）。历史线索只决定先后，不排除其他允许位置。

## 从历史确定目标后继续行动

“找到历史里的物体，确认它现在的位置”包含两步：从历史确定要找谁，再到当前场景找它。历史中没描述到目标，不能说当前场景没有；先按题面明确给出的目标搜索。只有目标完全无法确定时，才如实说明缺少哪条线索。

- 指定记录用 `mem_recall_episodes({"text":"历史 N","top_k":1})` 精确查询；N替换成题目里的编号。不要只查询“找物任务”而取回其他记录。
- 历史任务的目标读该记录的指令；不要把整段历史中任意出现的物体当作目标。
- 地图和历史只是搜索线索。确认现在位置必须启动原生 `task_start` 的 `kind=find`，等当前观察结果后回答。

## 参数示例

题目“在厨房找紫色的水壶”：`target="紫色的水壶"`，`detect_as="kettle"`，`areas=["厨房"]`，`only_areas=true`。如果target只填“水壶”，即使phrase写了紫色，视觉检查也可能只找任意水壶。

## 关系找物

“茶几上的水壶”要求现场看清承载关系，不等于导航到旧地图中任意水壶旁。`find` 的 `target` 保留“茶几上的水壶”，`detect_as` 填“kettle”，房间放入 `areas` 并按题面限制范围。不要把“在……上”改写为 `where.near`：原生工具可能把这种写法转为旧地图目的地导航，且“旁边”也不等于“上面”。保留完整原话在 `phrase`；无法核实关系时不能算找到。

## 执行

- 用 `task_start` 的 `kind=find` 执行上述计划。创建被拒绝时，读返回原因，修改对应参数再提交；不重复原封不动的失败计划，不把拒绝当作任务已启动。
- 已有活动任务时，先查 `task_status`，继续跟踪该任务，不能重复创建或在后台任务仍行动时宣布结果。
- 当前位置没看到，和已经找完整个范围，是两件事。需要模型选择下一步时，按已有证据选择尚未检查的候选、换一个可到达观察位置或转向核实。每次重试说明哪里变了；走不过去不等于目标不在。
- 看到了同类别物体，还要核实题目要求的颜色、外观或关系。工具说“可能”“没看清”，就保留这种不确定性；不要把“绿色物体形似手机”说成已确认绿色手机。

## 收尾

按原生搜索记录如实说：确认找到的对象和房间；或检查过哪些地方、哪里没看清、哪里没走到。不伪造搜索记录，不用猜测的位置补坐标，不额外提交像素或 XYZ。
最终回复由仿真桥保存和评分，评分结束后不再导航。时间用完但范围没查完，说明没有完成；不能说全屋没有。

## 迭代边界

只能把多道题共同暴露的流程问题改成通用做法。不得把题目编号、某道题答案、目标真实房间、私有布局、评分提示或上次测试发现的位置写进本文件。每版用同一组固定题完整测试；同集调优成绩不代表新题泛化成绩。
