# 精读、批注并归档 Zotero 论文

完整阅读论文，生成中文批判性分析，并在用户需要批注时创建 Zotero PDF 阅读器可显示的嵌入式 PDF 注释。始终把 Zotero 管理的源文件和数据库视为只读。

## 工作流

### 1. 检查来源

- 只读列出用户提供的目录，识别主论文、补充材料、网页快照和 Zotero 标记文件。
- 多个 PDF 并存时，根据文件名、元数据和首页判断主论文；证据仍不足时再询问。
- 记录标题、作者、年份、发表状态、DOI/标识符和官方项目链接。
- 按论文正式简称生成安全的文件名，例如 `Dynam3D`。

### 2. 完整阅读

- 阅读全部正文和相关补充材料，覆盖摘要、引言、相关工作、方法、关键公式、训练设置、主实验、消融、结论与局限。
- 直接核对表格中的方法、指标、数据划分和数值，不只复述作者结论。
- 若文本提取失败，依次尝试其他本地 PDF 库、页面渲染和 OCR；不得用摘要代替全文而不说明。

### 3. 规划中文批注

仅标注值得再次定位的证据，避免把整页涂满。默认每页不超过 5 条、全文约 15–35 条；短论文按比例减少。每条批注必须包含：

- `quote`：PDF 中可精确搜索的原文，优先选择 5–30 个词的唯一片段；
- `comment`：简洁中文说明，先写意义，再写必要的质疑或关联；
- `category`：以下五类之一；
- 可选 `page`（从 1 开始）和 `occurrence`（同一片段的第几次出现，从 1 开始）。

使用一致、低饱和且易区分的配色：

| 类别 | 用途 | 默认颜色 |
|---|---|---|
| `contribution` | 核心贡献、结论 | 柔和黄 |
| `method` | 方法、公式、关键设计 | 柔和蓝 |
| `evidence` | 数据、实验结果 | 柔和绿 |
| `limitation` | 局限、风险、无效假设 | 柔和红 |
| `question` | 疑问、待复现项 | 柔和紫 |

批注写作要求：使用中文；保持客观；明确区分论文事实、作者主张和阅读者推断；避免“很重要”等无信息评论。对关键数字注明评价条件，对方法注明输入/输出或关键假设，对局限说明可能影响。

### 4. 生成带批注 PDF

将批注计划保存为 UTF-8 JSON 数组，然后运行：

```powershell
python scripts/annotate_pdf.py --input <源.pdf> --output <简称-批注版.pdf> --annotations <批注.json> --report <批注报告.json>
```

- 脚本依赖 `PyMuPDF`；缺失时先报告依赖，仅在当前任务允许安装本地依赖时运行 `python -m pip install PyMuPDF`。
- 必须写入新文件，禁止以 Zotero 源 PDF 作为输出路径。
- 使用标准 PDF Highlight 注释和中文弹窗内容，确保 Zotero 可见；不要直接编辑 `zotero.sqlite` 或猜测 Zotero 内部注释表结构。
- “Zotero 原生注释”与“PDF 内嵌注释”不同。本 Skill 默认生成后者；若用户明确要求同步到 Zotero 注释侧栏，优先使用官方 Zotero API/可用连接器，并在操作前明确范围，绝不直接改数据库。
- 查看报告中的 `unmatched` 与 `ambiguous`。必须修正未匹配项；歧义项通过添加 `page`、扩大 `quote` 或指定 `occurrence` 消除。
- 打开或渲染若干含批注页面目视检查：高亮准确、不过度覆盖、颜色一致、中文弹窗完整。若阅读器不显示透明度，以颜色本身仍清晰为准。

### 5. 写中文分析

创建 `<论文简称>.md`，包括：基本信息、一句话总结、研究问题、方法总览与关键模块、训练数据与配置、主要实验结果、消融含义、主要贡献、批判性评价、复现启示、阅读结论。

保留关键数值、硬件、训练时长、数据规模和评价条件。分别标明论文报告的事实、作者声称的结论、阅读分析或推断。按主题引用相应页码；批注版存在时，可在 Markdown 中列出重点批注索引。

Markdown 数学公式使用常见预览器兼容的分隔符：行内公式写作 `$...$`，独立公式将 `$$` 分别放在公式前后的独立行。不要用 `\(...\)` 或 `\[...\]` 充当 Markdown 公式分隔符，因为部分 VS Code、KaTeX 或 MathJax 预览链会把它们显示为原始 LaTeX。源码编辑页显示 LaTeX 是正常现象，验收以 Markdown 预览中的渲染结果为准；不要为了规避渲染问题把公式截图化。

#### 论文原图与模块对应（按需）

仅在用户要求截图，或原图能明显帮助理解架构、实验、消融、定性案例或真实部署时嵌入图片；不要把所有图或整页 PDF 机械堆进笔记。

- 先渲染并目视检查含图整页，再按原图边界精确裁剪；使用足以看清小字的分辨率，排除相邻正文、无关表格和页眉页脚。
- 优先直接裁取论文原图并保留原始图号与 caption，不用 AI 重绘替代论文证据，也不在未说明的情况下改变图中内容。
- 将图片保存到 `<论文简称>/figures/`，使用稳定且有语义的文件名，例如 `fig2-system-overview.png`；在 Markdown 中使用相对路径 `./figures/...` 和有信息量的 alt text。
- 把图片紧邻放在它所支持的段落或模块，而不是集中放到文末。中文图注注明原论文图号、PDF 物理页码、对应的笔记模块，以及必要的证据边界，例如“仅为定性示例”或“不能替代数值消融”。
- 架构总览图应明确映射到笔记中的输入、编码器、投影/融合、决策与执行模块；实验图应映射到相应数据 split、指标或消融结论；失败案例应放在局限分析附近。
- 表格已有可靠文本转录时通常不再截图；数学公式继续使用可渲染的 LaTeX，不用截图解决 Markdown 公式兼容问题。

### 6. 建立归档

在当前工作目录创建：

```text
读论文/
  <论文简称>/
    <论文简称>.pdf
    <论文简称>-批注版.pdf    # 请求或生成批注时
    <论文简称>.md
    figures/                  # 请求插图或图片确有助于理解时
    <论文简称>-批注报告.json # 便于审计和修正
```

- 复制原始 PDF，绝不移动、重命名、覆盖或删除 Zotero 源文件。
- 已有目标时先检查；未经明确授权不得覆盖，使用带版本号的新文件。
- 仅在用户明确要求时改用其他输出位置。

### 7. 验证交付

- 确认所有预期文件存在。
- 比较源 PDF 与归档原版 PDF 的大小及 SHA-256；再次确认源 PDF 哈希未变化。
- 用脚本报告确认计划条数、成功条数、页码、类别、未匹配项和歧义项。
- 重新打开批注版，抽查 PDF 注释的类型、颜色、作者、中文内容及目标文本；至少渲染首页和含多类批注的一页检查视觉效果。
- 检查 Markdown 标题和必需章节；确认数学分隔符成对，不残留作为公式边界的 `\(...\)` 或 `\[...\]`。存在公式时，至少在目标 Markdown 预览器中目视检查一条行内公式和一条独立公式。报告准确输出路径、验证结果和任何限制。
- 存在插图时，逐一确认相对路径可解析、图片可打开、分辨率足够、裁剪不截断图或 caption、没有混入无关正文；在 Markdown 预览中检查每张图确实紧邻并对应所述模块，图号和 PDF 物理页码正确。再次确认截图过程未改动源 PDF。

## 失败处理

- 扫描版或乱码 PDF 无法可靠定位原文时，先 OCR 生成可搜索副本，再对副本批注，并明确标注该限制。
- 旋转页、跨栏或跨页片段匹配不准时，缩短为同一行或同一段内的唯一片段；禁止用大矩形猜测位置。
- 批注写入失败时保留原始 PDF 和 Markdown，报告失败项，不交付伪称完成的批注版。
- 不用网页摘要替代缺失论文内容。只有用户要求时效核验或需核对外部书目信息时才浏览，并单独引用来源。
