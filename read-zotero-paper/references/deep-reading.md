# 详细精读：把创新解释成可核查的机制

在用户要求详细精读、比较旧方法或解释创新时使用。篇幅服从问题复杂度；对话应给出实质性分析，归档笔记保存完整证据和复现信息。无需把下列小节原样当成最终标题。

## 1. 先界定研究问题，再复原旧方法

用具体输入、期望输出、使用条件描述任务。解释困难发生在哪个环节，以及为什么已有能力不足以直接解决。明确论文改变的是任务定义、模型结构、训练目标、数据、推理策略、系统工程还是评估方法；一篇论文可能涉及多层。

旧方法不能只写“传统方法能力弱”。选择论文直接比较且最接近的两三条路线，说明它们如何从输入得到输出、哪些决策由人或外部代码控制、哪些由模型学习。优先依据论文相关工作和实际基线；只有判断新颖性需要时才查前作原文，并标明哪些已直接阅读、哪些只是本文对前作的概括。

避免稻草人比较：例如带工具的旧 agent 也能执行代码、自我纠错；新工作可能是把调度策略学进模型，而不是首次允许执行工具。没有广泛文献验证时，把“首次”保留为作者主张。

## 2. 每个核心创新形成完整解释链

逐项回答以下问题，而不是罗列贡献名称：

1. **以前怎么做？** 给出可运行的旧方案或对照策略。
2. **瓶颈在哪里？** 说明具体失败机制和适用条件，区分作者动机与已验证现象。
3. **改了什么？** 定位到数据、模块、损失项、动作协议或训练阶段。说明输入、输出以及连接关系。
4. **为什么可能改善？** 展开因果机制；如果只是合理解释而非独立验证，标为阅读分析。
5. **如何运行？** 给出一段小例子、伪代码或必要公式，使用户能追踪信息流。
6. **证据是什么？** 绑定实验、消融、图表与物理页码。缺独立消融时明确说明。
7. **付出什么代价？** 说明新增训练数据、算力、工具依赖、假设、失败情形和未证明之处。

通常用一个紧凑对照表串起“旧方法—瓶颈—本文改动—证据”，随后用段落解释最重要的机制。不要把整篇分析塞进宽表格。

区分：已有技术直接复用、已有技术在本任务的新组合、有实验证据的独立设计、工程整合、资源或基准贡献。使用 SFT、RL、蒸馏、检索或注意力本身不等于发明这些技术。

## 3. 贯通训练与推理，防止只会复述架构图

为学习型方法分别说明训练和推理，避免把离线数据合成中的多个 agent 误写成部署时的多个 agent。分别确认哪个组件生成动作、哪个执行动作、环境反馈是否真实执行获得、何时更新参数、何时停止。

按论文适用范围记录：基础模型/初始化，数据来源及去重/划分，样本量与计量单位，各阶段目标及顺序，监督信号或奖励来源，上下文长度，工具环境，硬件、训练时长、超参数。论文没写的内容不能从常识补齐。公开代码与论文描述不一致时保留差异，不能静默替换。

公式只选有助于解释贡献的部分。定义符号、取值、优化方向，并说明某项增大时行为如何改变。检查奖励尺度、归一化、无效输出和边界条件；论文没有说明时写成复现疑问，不自行发明定义。

至少用一条完整例子串起输入→中间表示/动作→反馈→修正→输出。论文真实案例与教学假设必须标明；教学例子不能冒充已执行结果或论文实验。

## 4. 实验必须支持到“这项改动”

为主要结果保留数据集、划分、指标定义与方向、基线名称/模型版本、实际数值和差值。成功率、准确率、报告质量、模型任务性能、成本分别解读；百分比指标的绝对差写“百分点”，不要混淆相对提升。

对照需留意基础模型、训练数据量、上下文/工具/重试预算、评测时间、是否直接沿用他文数字。若非严格同条件，应限制结论；无统计检验或重复种子时，不把小数差异写成显著提升。

主结果证明整体系统表现，消融才更接近证明组件作用。逐项说明消融移除了什么、哪些同时变化、哪些结论无法分离。例如移除多阶段训练后分数下降，不自动证明全部收益来自 RL，而不是额外 SFT 数据。

必须核对不利结果：是否仅平均分领先、部分领域退化、容易题不占优、任务成功但最终质量偏低。避免“全面超越”“解决了”“证明原因”超出表格证据。

对开放式评估说明任务数量、来源、评分器、评分准则和是否有人类/程序化核验。特别区分报告写得完整与数字真实、执行成功与统计正确、相关性与因果性。自建基准、训练/测试同领域、评委偏好或缺少置信区间属于证据边界，不是可以无证据断言的数据泄漏或造假。

## 5. 批判性评价要有具体着落

优先提出改变结论可信度的少量问题，每个问题链接到原文设计或实验：例如奖励鼓励更多工具调用，是否奖励了无效长度；报告评委只看到文本，是否验证不了数据来源；成功率上升但预测性能下降，是否只是更会完成流程。

将“论文明确承认”“从证据观察到”“尚待验证的推断”区分开。案例中的异常数字要先看原图，排除 OCR、坐标轴、单位和版式错误；仍无法确认时报告疑点，不直接判为幻觉。

给出可操作的后续验证：应增加哪个控制组、固定哪些预算、检查哪类失败、用什么指标判定。复现启示应说明值得迁移的机制及必要前提，不机械建议复现整篇论文。

## 6. 组织交付与验收

对话先用清晰的一段回答“它最核心的改变”，再展开旧方案、关键创新、实例、证据与局限。用户要详细时，不得只给摘要和文件链接。归档笔记可更完整，包含版本/来源、训练配置、逐项证据、未报告信息及复现建议；已有输出需遵守主 skill 的版本保护规则。

交付前检查：

- 每个主要创新是否有旧方案、具体机制和证据边界，而非仅有名称？
- 读者能否复述一条完整执行过程，并分清训练、部署和数据合成？
- 所有关键数值是否能回到同一版本的表格/图，差值与单位是否正确？
- 是否把复用技术当新发明，把作者主张当事实，把整体提升当组件因果证明？
- 是否覆盖最强反例和最影响可信度的局限，缺失信息是否明确标注？
- 正文解释是否自足，插图是否真正解释机制，归档链接是否可打开？

文件和格式检查通过不等于内容精读通过。无法完成某部分阅读或验证时，准确标明范围。
